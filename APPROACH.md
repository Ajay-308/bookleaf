# Approach

I prioritised the end-to-end author support loop: sign in, inspect a book and its royalty figures, open a ticket, triage it as an operator, send a reviewed response, and see that response in the author's portal without a manual refresh. The sample dataset is seeded into PostgreSQL and includes production-stage books and zero/low royalty edge cases.

The implementation keeps a small React client separate from an Express REST API. PostgreSQL, Prisma ORM, and an idempotent seed provide a relational store for authors, books, tickets, and messages. The API enforces author ownership and admin-only operations at the server boundary; the browser's role-based navigation is not treated as security. Public replies and internal notes are stored separately by visibility.

AI is optional rather than a dependency for ticket intake. Groq is the selected low-cost/free-tier evaluation provider, accessed through its OpenAI-compatible chat-completions API. When configured, a compact prompt classifies into fixed enums and response drafting starts when an admin opens a ticket, using only the relevant BookLeaf policy, the bounded query, and book status. If the provider is absent, slow, rate-limited, or unavailable, local rules classify the ticket and the admin still receives an editable safe draft. Admins retain control over the classification, priority, status, and final message.

The API includes basic security headers, request-size limits, and in-memory API/login/AI throttles, and requires a sufficiently long JWT secret in production mode. The PostgreSQL schema has a checked-in Prisma migration; a production rollout should apply migrations through a controlled deployment step. Remaining production work includes persisting rate limits in a shared store when horizontally scaled, using managed secrets and stronger session/refresh-token controls, and adding audit trails, monitoring, file storage/malware scanning, and broader automated integration tests. I would evaluate classification quality on a labeled query set and measure response usefulness, latency, quota behavior, and token spend before expanding AI automation. Groq's free tier is useful for a demo but does not guarantee production capacity or availability. The current eight-second polling interval is a deliberate simplicity trade-off; a larger deployment could use server-sent events.
